<objective>
Add an opt-in `LAB_COMPARE` integration to `scripts/sweep.sh` that shells out to LAB's existing
`evaluation.compare` module as the final step of a sweep (LAB-02), without adding any aggregation
logic to the runner (LAB-01 — runner stays thin). Document the usage and the verified `config.json`
compatibility gap in `docs/adapter-guide.md`.

Purpose: Let an operator run LAB's comparison/report generation immediately after a sweep, using
LAB's own tool against the results just produced — preserving the locked "no new aggregator in the
runner" decision. The `config.json` gap (LAB's `collect_runs()` skips run dirs lacking `config.json`,
which runner-produced dirs lack) must be documented so `LAB_COMPARE` is used against LAB-native
results, not silently producing empty output.

Output: `run_lab_compare()` function in `scripts/sweep.sh` wired into `main()`, plus a
`LAB_COMPARE` section appended to `docs/adapter-guide.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env (LAB_COMPARE, LAB_COMPARE_ARG) → sweep.sh | Operator-supplied scope + target name cross into a subprocess invocation |
| sweep.sh → harvey-labs evaluation.compare subprocess | Runner shells out to an external Python module |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-08 | Input Validation | `LAB_COMPARE` value | mitigate | `case` matches only task/area/all; any other value errors to stderr and returns 1 (ASVS V5 minimal control per RESEARCH security domain) |
| T-07-09 | Tampering | `LAB_COMPARE_ARG` passed to evaluation.compare | mitigate | Value quoted as a single `--task`/`--area` argument (`"$arg"`); not eval'd; passed to argparse which treats it as a string |
| T-07-10 | Information Disclosure | empty/misleading compare output against runner dirs | accept | Documented config.json gap (LAB-01 doc); operator points LAB_COMPARE at LAB-native results; no data leak |
| T-07-11 | Elevation of Privilege | subprocess inherits sweep env | accept | Subprocess is LAB's own tool in a `( cd "$LAB_PATH" && uv run ... )` subshell; no privilege escalation surface |
</threat_model>

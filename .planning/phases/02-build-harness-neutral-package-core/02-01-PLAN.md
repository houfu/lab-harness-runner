## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pyproject.toml → uv install | Package names in requires = [...] are fetched from PyPI |
| task_id / run_id input → filesystem paths | String values become path components; unsafe strings cause path traversal |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | pyproject.toml `requires` (uv_build package) | accept | uv_build is Astral's official build backend (~same org as uv); PSF-sponsored black; both are [ASSUMED] per legitimacy audit but provenance is extremely high |
| T-02-02 | Tampering | TaskSpec.task_id → filesystem path | mitigate | task_reader.py (Wave 2, plan 02) applies _reject_unsafe_relative_path guard before joining to lab_path; adapter.py itself stores only the string |
| T-02-03 | Tampering | RunResult.end_state string value | accept | end_state is only written to metrics.json for diagnostics; LAB evaluator ignores it; no code branches on it in this phase |
| T-02-SC | Tampering | uv add installs (uv_build, black, pytest) | mitigate | slopcheck unavailable; packages are [ASSUMED] — both uv_build (Astral) and black (PSF) are decade-old with >100M/month downloads; pytest is de facto standard. Human verify if strict policy requires it. |
</threat_model>

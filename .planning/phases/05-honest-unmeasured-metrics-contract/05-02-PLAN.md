<objective>
Propagate the null-vs-zero distinction through the batch-summary path: `write_batch_summary` stops coercing absent LAB metric fields to `""`; `build_summary` annotates each row with `metrics_provided` and emits a top-level `unmeasured_counts` dict; list fields get a `lengths` sub-block in `variance`; and `_batch_row` in `scripts/run_benchmark.py` lets a JSON-loaded `null` flow through to the batch row unchanged.

Purpose: This is the aggregation half of CON-02 (skip null in mean/sum/variance) and all of CON-03 (visible annotation of unmeasured rows in the batch summary).

Output: Two files updated — `lab_harness_runner/aggregation.py` (annotation + variance shape + row normalization) and `scripts/run_benchmark.py` (`_batch_row` removes the `""` second-arg default).
</objective>

The cleanest implementation is to define a small helper inline like `def _default_for(field: str) -> object: return None if field in LAB_METRIC_FIELDS else ""` and use `normalized = {field: row.get(field, _default_for(field)) for field in REQUIRED_ROW_FIELDS}`.
```python
"input_tokens": run_summary.get("input_tokens", metrics.get("input_tokens", "")),
```

```python
"input_tokens": run_summary.get("input_tokens", metrics.get("input_tokens")),
```

The semantics after the change: if the per-run summary has the key, use it; otherwise read the metric from `metrics.json` (which may be `None`); if the metric is missing from `metrics.json` entirely, the second `get` returns `None` (the `metrics.get(key)` single-arg form returns `None` for missing keys). So the chain is `run_summary_value ?? json_loaded_metric ?? None` — which is the correct "unmeasured if absent" semantics for the new contract.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| metrics.json on disk → _batch_row | The per-run `metrics.json` may have `null` for unmeasured fields; the row-builder must let the null through |
| _batch_row → write_batch_summary | The row dict's `None` values must reach `build_summary` so `metrics_provided` and `unmeasured_counts` reflect the unmeasured signal |
| write_batch_summary → build_summary | The row normalisation must use `None` for absent LAB metric fields (not `""`), so `build_summary`'s `row.get(field) is None` check is correct |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03 | Information Disclosure | `unmeasured_counts` exposes which fields were unmeasured per batch | accept | This is a metadata-only summary, not security-sensitive. The shape mirrors the per-row nulls; no new disclosure. |
| T-05-04 | Tampering | Row normalisation `None` default could mask missing data as "unmeasured" | mitigate | The `metrics_provided` boolean is `True` only when ALL LAB metric fields are non-null; rows with any null get `False`. The `unmeasured_counts` dict tracks per-field counts so a consumer can detect a row that is "all null" vs "one field null". |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed. Stdlib `json`, `statistics` only. |
</threat_model>

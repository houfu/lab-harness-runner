# Requirements

## Functional

- Read LAB task metadata from `task.json`.
- Support task instructions stored inline or in `instructions.md` after live
  verification confirms the current LAB shape.
- Extract expected deliverable filenames from `criteria[].deliverables`.
- Build a `TaskSpec` containing instructions, documents directory, expected
  deliverables, and run id.
- Create `results/<run-id>/output/` for each run.
- Define an adapter contract equivalent to
  `run(task_spec, output_dir) -> RunResult`.
- Implement a nanoclaw-lq adapter that dispatches task instructions into the
  selected agent group.
- Mount task documents read-only and the run output directory read-write for
  nanoclaw.
- Wait for a terminal `STATUS:` signal from nanoclaw.
- Apply a wall-clock timeout and record timeout separately from clean completion.
- Validate that expected deliverable filenames exist before scoring.
- Write `metrics.json` using available `RunResult` metrics and safe defaults for
  missing values.
- Invoke LAB's evaluator to produce `scores.json`.
- Preserve LAB-generated reports and dashboards.
- Support multi-task and multi-seed runs after the single-task path works.
- Document how third-party harnesses implement the adapter contract.

## Quality

- Keep package-owned code harness-agnostic.
- Keep environment, dispatch, completion, and harness metrics inside adapter
  implementations.
- Avoid coupling to LAB's harness orchestrator internals.
- Verify live LAB and nanoclaw-lq interfaces before relying on notes from the
  source brief.
- Present benchmark results as whole agent-system outcomes, not model-only
  outcomes.
- Report variance before making multi-task performance claims.

## Deferred

- Additional adapters beyond nanoclaw-lq.
- Upstream LAB documentation PR for stable task/result contracts.
- Public package publishing and broader community onboarding.

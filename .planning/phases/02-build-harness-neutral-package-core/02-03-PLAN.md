<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| expected_deliverables list → output_dir file existence checks | Filenames from TaskSpec become filesystem path components inside output_dir |
| run_id, task_id strings → subprocess CLI arguments | These strings are passed as --run-id and --task arguments to the evaluator subprocess |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | expected_deliverables filename → output_dir path join | accept | Filenames originate from task.json criteria[].deliverables, validated as str type in task_reader.py; they do not traverse outside output_dir because output_dir / name only descends |
| T-02-07 | Tampering | run_id / task_id as CLI arguments to subprocess | accept | Arguments are passed as list elements (not shell-interpolated string); subprocess list form prevents shell injection; run_id / task_id originate from caller-controlled code in this phase (fake_run.py UUID) |
| T-02-08 | Elevation of Privilege | subprocess.run with check=True invokes uv as external process | accept | uv is a trusted local tool; cwd is restricted to lab_path (a known local directory); no shell=True; no user-controlled PATH manipulation |
| T-02-09 | Denial of Service | judge_model passed to evaluator invokes LLM API | accept | score_run is only called with --score flag in fake_run.py; explicit user opt-in; API cost is user's responsibility |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan (stdlib only) |
</threat_model>
